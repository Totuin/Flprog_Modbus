# Flprog_Modbus 1.0.1 — библиотека Modbus для FLProg

Ревизия библиотеки FLProg версии 1.0.0. Содержит Modbus RTU и Modbus TCP в режимах Master/Slave, RTU-over-TCP, мост UART ↔ TCP, интеграцию KaScada Cloud и таблицы регистров.

## Подключение

* RTU: `#include <flprogModbusRTU.h>` — требует `Flprog_Utilites` и UART-исполнителя FLProg.
* TCP: `#include <flprogModbusTCP.h>` — дополнительно требует совместимую реализацию `flprogEthernet.h` из установленного сетевого пакета FLProg.
* Мост: `#include <flprogModbusBridge.h>` — требует и UART, и сетевой интерфейс.

При замене библиотеки сохраните исходную версию отдельно **вне** каталога `libraries`, иначе Arduino может выбрать не ту версию. Драйверы RT_HW и `FLProg_Network` этой ревизией не изменялись.

## Реализованные функции Modbus

FC01/FC02 — чтение катушек и дискретных входов; FC03/FC04 — чтение регистров; FC05/FC06 — запись одной катушки или регистра; FC15/FC16 — групповая запись. Сохранён прежний лимит FLProg до **25 элементов на запрос**. Адреса в API нулевые (`0` соответствует первому адресу кадра Modbus). Существующие имена методов и формат кадров не изменены.

## Что исправлено в 1.0.1

- FC15: упаковка катушек в байты с правильным порядком битов и количеством байтов на границах 7/8/9.
- FC01/FC02: очистка битов выходного буфера перед формированием ответа.
- FC03/FC04: запись в выходной буфер только при наличии места для обоих байтов регистра.
- Исключения Modbus: сохраняется исходный адрес ведомого устройства, а не принудительный `1`.
- FC05: отклоняются значения, отличные от `0x0000` и `0xFF00`; FC15/FC16: проверяется поле количества байтов; запросы нулевой длины отклоняются.
- CRC: безопасная обработка слишком короткого кадра; RTU: проверка свободного места для CRC, сброс переполненного входного кадра.
- Время отправки UART: устранено целочисленное усечение при вычислении длительности кадра; предусмотрены некорректные значения входных параметров.
- `ModbusTable`: исправлено повторное создание массивов и копирование объектов, переполнение стека при поиске редкого следующего адреса и кэш min/max.
- Служебные указатели Master/Slave и счётчики начального состояния получают определённое нулевое значение.

**Важно:** массив адресов, переданный в `ModbusTable(..., int32_t* addresses)` или `init(..., addresses)`, остаётся в собственности вызывающего кода. Не удаляйте и не изменяйте его до конца использования таблицы. Сгенерированные библиотекой массивы принадлежат таблице, освобождаются при повторной инициализации/уничтожении. Копирование `ModbusTable` создаёт независимую копию. При увеличении размера `init(size)` массив адресов становится собственным, если прежде был внешним.

## Проверка

`tests/host/run.sh` запускает автономные тесты ядра Modbus (GCC/Clang, C++11, ASan/UBSan) для двух размеров буфера: 64 и 250 байт. В `tests/host` находятся только заглушки Arduino/UART/Ethernet для тестовой машины. Тест исходников не является испытанием на контроллере.

`examples/ModbusTableSmoke/ModbusTableSmoke.ino` — без сетевого оборудования и без RS-485, проверяет создание таблицы и CRC. Остальные примеры из исходного архива сохранены, включая Modbus RTU/TCP и мосты.

## Известные ограничения

1. Реальный обмен Master/Slave по RS-485 и Ethernet/Wi-Fi, а также повторный обмен после потери соединения в 1.0.1 не проверялся. Отдельно проверить TCP через W5100/W5500 с учётом существующего исправления от 20.09.2026.
2. В исходном `TO-DO.md` отмечены вопросы к Master RTU, ограничению групповых запросов, состоянию сети, мосту и Cloud. Они остаются открытыми, чтобы не менять штатный алгоритм без аппаратной проверки.
3. Таблицы и списки устройств, созданные с помощью `new` внутри главных объектов Master/Slave, в отдельных сценариях живут всё время работы контроллера. Полная политика владения ими требует отдельного аудита; не создавайте и не удаляйте такие объекты многократно в `loop()`.
4. Для любой промышленной установки отдельно проверяйте реакции на пропадание связи, тайм-ауты и безопасное состояние исполнительных механизмов. Компиляция не заменяет эти испытания.
